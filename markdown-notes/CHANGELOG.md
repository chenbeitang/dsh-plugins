## 版本历史

### 1.9.1 — 代码块语言下拉样式美化

- 语言下拉改为胶囊按钮外观：去掉浏览器默认箭头，改用主题感知的自定义箭头。
- 默认透明 / 次要文字色，悬停时显示浅色底和描边，聚焦时显示主题品牌色描边与轻量光环。
- 代码头高度 / 间距微调，箭头在聚焦时旋转，深色 / 浅色主题都使用主题 token。
- 只改外观，语言切换、Markdown 回写和代码高亮逻辑不变。

### 1.9.0 — 代码块语言类型显示与切换

- 每个围栏代码块顶部新增代码头，显示当前语言下拉；未指定语言时显示 `text`。
- 支持在渲染视图直接点击下拉切换语言：
  - 自动改写 Markdown 围栏行（保留围栏符号 / 缩进）；
  - 立即重新渲染并应用对应的语法高亮；
  - 代码正文不被修改。
- 支持常见语言：text、java、javascript、typescript、python、c、cpp、csharp、go、rust、kotlin、swift、php、ruby、sql、xml、html、css、json、yaml、shell、powershell、dockerfile、diff、markdown；当前语言不在列表时自动补充。
- 代码块改为外层容器 + 顶部代码头 + `pre`，光标映射仍以 `pre` 的 `data-line` 为准，不破坏分栏光标定位。
- Markdown 回写会忽略代码头，只输出围栏代码；新增语言下拉、回写与切换语言的测试。

### 1.8.5 — 修复多行代码块光标定位错位

- **根因**：代码块的一个 DOM 文本节点可能包含多行（`"first\nsecond"`）。`collectRenderedSegments` 会把这个文本节点拆进多个行段，但 `previewSelectionToPosition` 在把渲染光标映射回源码时，只按文本节点匹配，没有检查光标偏移是否落在该行段的 `[start, end]` 区间内。
- 结果：点击代码块第二行及之后的行时，映射总是命中第一个包含该文本节点的行段，光标回跳到上一行 / 更早的行。
- **修复**：匹配行段时必须同时满足 `part.node === container` 且 `range.startOffset` 位于 `part.start` ~ `part.end` 之间；表格单元格的同类映射也加上相同边界检查。
- 新增多行代码块「第二行 → 正确源码行」回归测试。
- 原生多行代码、语法高亮后的代码块都适用。

### 1.8.4 — 格式块菜单改为指定顺序

- 原文 / 渲染视图共用菜单顺序调整为：
  代码块 → 引用 → 分割线 → 表格 → 待办列表 → 有序列表 → 无序列表 → 三级标题 → 二级标题 → 一级标题 → 正文。
- 默认高亮项现在是「代码块」。
- 菜单渲染与键盘选择顺序同步更新，新增完整顺序断言。

### 1.8.3 — 格式块菜单顺序倒序

- 原文 / 渲染视图共用的格式块菜单选项顺序整体倒序。
- 新的顺序为：分割线、表格、代码块、引用、待办、有序列表、无序列表、三级标题、二级标题、一级标题、正文。
- 菜单、快捷键选择与测试断言同步更新。

### 1.8.2 — `/`、`、` 改为非破坏式触发

- 中文输入法输入 `、` 时，字符会**正常写入文档**，同时弹出格式块菜单；不再阻止字符输入。
- `/` 也采用同样行为：先输入字符，菜单只是可选项。
- 不选择菜单、按 Esc、继续输入其他字符时，触发字符都保留在文档中。
- 选择格式块时，才移除该触发字符并用对应的 Markdown 块替换。
- 原文视图和渲染视图都改为 `input` / `compositionend` 后检测，兼容中文输入法组合输入。
- 修复之前 `、` 无法输入、按 Esc 后字符丢失的问题。

### 1.8.1 — 格式块菜单扩展到原文视图

- 原文 textarea 的空行中，首字符输入 `/` 或 `、` 同样弹出格式块菜单。
- 菜单与渲染视图共用同一套组件、图标、文案和键盘交互。
- 菜单定位使用隐藏 mirror 精确测量 textarea 光标位置，随滚动 / 光标位置调整。
- 选中后把块标记写入源码空行，自动补齐前后空行，并把光标放到标题 / 列表标记后、代码块内、表格首个单元格或分割线末尾。
- 支持 `beforeinput` 兜底，覆盖中文输入法产生 `、`。
- 原文视图只处理空行首字符，普通行内斜杠仍按字面输入。

### 1.8.0 — 渲染视图格式块菜单（飞书式 `/` 菜单）

- 渲染视图的**根级空段落**中，首字符输入 `/` 或 `、` 会弹出格式块菜单。
- 菜单项：正文、一级 / 二级 / 三级标题、无序列表、有序列表、待办列表、引用、代码块、表格、分割线。
- 交互：
  - 菜单跟随光标定位，带图标、名称与说明；
  - `↑` / `↓` 选择，`Enter` 插入，`Esc` 关闭，也可直接鼠标点击；
  - 点击菜单不会抢走编辑器焦点，保持当前光标位置。
- 插入时直接把块标记写入 Markdown 源码（不是只改 DOM），并自动在空行前后补齐分段；插入后光标落到新块内。
- 支持 `beforeinput` 兜底，覆盖中文输入法产生 `、` 的情况；只在根级空块触发，普通段落里输入斜杠仍按字面输入。
- 新增表格图标与中英文菜单文案；新增菜单渲染测试。

### 1.7.0 — 代码块多语言语法高亮

- 围栏代码块按语言标记（` ```java `、` ```xml ` 等）进行语法高亮，不再只以等宽纯文本展示。

### 1.6.0 — 文件管理器中打开 + 拖动移动

  - 目标文件夹高亮；禁止拖到自身、自身子级、当前父目录或已有同名条目的位置。
  - Host 新增 `POST /api/entry/move`，使用 `fs.rename`，同步更新收藏与最近打开路径。
  - 拖动前自动保存当前笔记；活动笔记或其所在文件夹被移动后，客户端路径同步更新。
- 新增 `entry/reveal`、`entry/move` HTTP 路由、`host/reveal.js` 与对应中英文文案。

### 1.3.1 — 修复引用块（`>`）字符定位错位

- **根因**：渲染器在块与块之间用换行文本节点分隔（如 `</p>\n<ul>`）。`collectRenderedSegments`
  把这些纯空白文本节点误判成空行段，使引用块内 `<p>` / `<ul>` / `<p>` 之间多出空段；
  行号到渲染段的索引整体后移，导致以 `>` 开头的引用块字符定位错位。
- **修复**：忽略纯空白文本节点，只保留 `<br>` 与代码文本中真实的换行空段；引用块行段数量与源码可见行数恢复一一对应。
- 同时处理：
  - DOM Selection 落在元素节点（而非文本节点）时用 `comparePoint` 对齐最近文本字符；
  - 列表项正文以 `>` 或 `#` 开头时，不再被误当成块级标记剥掉（只剥离引用前缀和一个标题/列表标记）；
  - 新增「引用块 + 列表 + 段落」「渲染块之间的空白文本节点」回归测试。

### 1.3.0 — 双端光标与字符级定位

## 已知边界

- Markdown 格式字符（`#`、`*`、`~`、反引号、列表标记等）在渲染侧没有独立可见字符，光标位于标记内部时会贴到最近的可见字符。
- 图片 alt 文本与链接 URL 在预览中不显示，无法作为定位目标；会在附近文字上兜底。
- 极少数复杂结构（嵌套引用中的表格、HTML 混排、列表续行等）可能退回行级几何近似。
- 渲染视图内新建、尚未带 `data-line` 的段落不会立即具备字符级映射（原文一侧编辑后会重新渲染补齐）。
- 光标提示只在分栏模式生效；另一侧当前滚动位置看不到目标内容时，光标会隐藏。
